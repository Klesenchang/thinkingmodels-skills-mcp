# ThinkingModels · 学习复盘

把一个具体模型和一次真实情境、行动或反馈连接起来，检验它何时有用。使用用户的语言，保持原任务和事实边界。简短学习问题可以直接解释并给一个应用动作，不要求用户完成整套复盘。

## 工作方式

1. **找到具体锚点。** 优先沿用用户指定的模型与案例。只有泛泛的“学习模型”时，可先给一个范围明确的应用示例，或在缺口真正阻塞时问一个问题；每轮最多一个。不要凭空制造用户经历、成果或动机。
2. **恢复当时的信息。** 复盘历史决定时，区分当时目标、可见信息、假设、选择与后来反馈。保留有关日期、来源和口径；未知就写未知。后来的结果不能冒充当时已知，不能为了使故事顺畅而改写记录。
3. **把模型变成可检查的判断。** 简短说明它提示看什么、依赖什么条件、可能忽略什么，再把它对应到案例中的一个具体观察或选择。不要只解释定义，也不要因为知道模型名称就宣称已经掌握或应用成功。
4. **用反馈检查适用性。** 把观察事实与因果解释分开。比较原预测和实际反馈，考虑替代解释、时机与环境变化；结果好不自动证明过程好，结果差也不自动证明模型无效。附一个最强反例：在什么条件下，这个模型会误导本案。
5. **形成一次下一轮行动。** 选择继续、修改或暂时放下哪条判断，并说明依据。给一个最小练习或实验，包含触发情境、要做的动作、要记录的信号与回看时间。记录只覆盖用户提供或实际观察的信息，不把计划写成完成，不夸大学习或业务效果。

## 交付尺度

通常给出**当时知道什么 → 模型对本案改变了哪个判断 → 反馈支持 / 不支持什么 → 下一次怎样检验**。若模型没有改变行动，明确说明并考虑换用更简单的解释，不为保留框架而增加术语。

需要区分事后解释与当时判断时，可读 [学习复盘示例](references/worked-example.md)。只有确实需要核对模型知识且已有工具时，才读 [可选知识访问](references/knowledge-access.md)；无需联网即可完成本技能。
