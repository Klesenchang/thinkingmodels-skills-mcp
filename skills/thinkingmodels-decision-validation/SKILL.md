# ThinkingModels · 决策验证

帮助用户做一项可解释、可验证的选择。保持用户的决策范围与既有授权，使用用户当前的语言。简单、低代价的选择给简短比较与下一步即可，不强制矩阵、打分或长篇模型分析。

## 工作方式

1. **确定这次到底选什么。** 沿用用户已有选项、标准、期限与不可突破的条件。缺少的标准可提出暂定建议并标明；只有会阻塞比较的缺口才追问，每轮最多一个问题。允许“暂缓”或“维持现状”成为相关选项，但不擅自扩张候选范围。
2. **按用户的标准比较。** 把硬约束与偏好区分开。少量选项可用短表写明收益、代价、证据、未知项；定性事实就用定性表达，估计采用有依据的范围。不要编造成功率、权重或精确总分。用户要求评分时，说明评分规则和证据基础，保留敏感假设。
3. **找出真正改变选择的取舍。** 说明哪些后果容易撤回、哪些会留下资金、时间、关系或迁移成本，以及影响范围。可逆不代表没有代价；不可逆也不自动意味着不能选。指出推荐依赖的关键假设与最强反例，并说明什么证据会推翻当前偏好。
4. **设计一次有边界的验证。** 优先验证会改变选择、且目前最不确定的假设。给出动作、投入上限、观察期限、证据与判读规则；阈值没有依据时先确定基线，不硬造数字。测试应保留可停止或回退的路径，不把“试验”变成默认承诺。
5. **把分析与执行区分清楚。** 在授权范围内可准备可审阅的方案或草稿；本技能不授予付款、签约、公开发布、删除数据或其他高影响操作的执行权。若用户已明确授权具体执行，仍遵守实际工具与任务边界。

## 交付尺度

给出**倾向与依据 → 关键取舍和未知 → 最强反例 / 改变选择的条件 → 一次最小验证**。证据不足时可以保留选择，不必硬选赢家；已完成比较不等于结果已经兑现。

面对看似有精确 ROI、却缺少关键假设的决定，可读 [决策验证示例](references/worked-example.md)。需要补充具体模型知识且已有工具时，才读 [可选知识访问](references/knowledge-access.md)；本技能可完全离线使用。
